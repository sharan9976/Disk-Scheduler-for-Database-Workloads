Why Database Hotspots Starve Far-Away Requests

In database OLTP workloads, B-tree root index blocks and frequently accessed buffer pages create high request density in narrow cylinder ranges. SSTF greedily serves requests in the local cluster, continually overtaking older requests located on outer or inner tracks. Algorithm Reference & DB Trade-offs

Architectural characteristics for database storage engines and disk controllers.

FCFS

First-Come First-Served

Processes I/O requests strictly in the order they were submitted by queries.

Pros:
  • Completely fair (0 overtaking guaranteed).
  • No starvation possible.
  • Trivial O(1) queue implementation.
Cons:
  • Catastrophic head thrashing across tracks.
  • Highest total seek latency for random/hotspots.
Database Context: Ideal only for dedicated append-only write-ahead log (WAL) streams.
SSTF

Shortest Seek Time First

Greedily selects the pending request nearest to the current head position.

Pros:
  • Substantially reduces total seek distance.
  • High raw I/O throughput in synthetic tests.
Cons:
  • Severe risk of starvation for boundary tracks.
  • High response-time variance (poor SLA guarantees).
Database Context: Can delay checkpoint flushes or cold table queries indefinitely while hot index queries dominate.
SCAN

Elevator Algorithm

Sweeps toward the disk boundary serving requests, then reverses direction at track D-1.

Pros:
  • Upper bound on starvation: every request served within 2 sweeps.
  • Much lower seek distance than FCFS.
Cons:
  • Unfair to tracks just behind the head when it reverses.
  • Mandatory trip to disk boundary (D-1) even if empty.
Database Context: Excellent balance for mixed OLTP queries and sequential table scans.
C-SCAN

Circular SCAN

Sweeps in one direction to track D-1, then rapidly returns to track 0 without serving requests on the return.

Pros:
  • Most uniform wait-time distribution across all cylinders.
  • Eliminates the bias favoring middle tracks in bi-directional SCAN.
Cons:
  • Extra seek distance incurred by the full-disk return jump.
Database Context: Gold standard for multi-tenant database clusters where predictable tail latency (p99) is required.
💡

Final Architectural Conclusion

SCAN and C-SCAN provide the optimal engineering compromise between physical seek efficiency and fairness. While SSTF consistently yields the lowest seek distance in localized database hotspots, its high overtaking penalty creates unacceptable tail latencies (starvation) for cold data queries. FCFS guarantees total fairness with zero overtaking, but imposes extreme mechanical seek penalties that cripple overall transaction throughput.
